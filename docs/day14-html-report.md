# Day 14：HTML 报告 v1

> 项目三第 2 周 · 把评测结果变成产品经理和算法同学都能直接用的决策材料。

## 一、报告结构（对应「坑 8：报告只有数字没有结论」）

报告顺序刻意从「结论」到「证据」，不完全按数据层级排列：

| 区块 | 内容 | 回答的问题 |
|------|------|-----------|
| 1. 结论区 | 总分 + 红黄绿状态 + 一句话主因 + 3 条行动项 | 能不能上线、先改什么 |
| 2. 指标明细 | 7 个指标卡 + 进度条，低于 50% 标红 | 具体差在哪 |
| 3. 数据集横向对比 | 黄金集 / 对抗集 / 边界集 三行对比 | 安全性和边界表现如何 |
| 4. 类别分布 | badcase 按业务类别横向柱状 | 集中在哪类业务 |
| 5. Badcase 明细 | 可展开：问题 / 回答 / 标准答案 / 失败指标 | 具体错成什么样 |
| 6. 原始数据 | data URI 下载全部用例 JSON | 想自己分析怎么办 |

领导只看第一屏就能拿到「不可上线 + 答非所问 + 先接真实 LLM」这个结论，往下翻才是佐证。

## 二、实现（`scripts/generate_report.py` + `templates/report.html`）

- **Jinja2 模板**渲染，模板只负责展示，结论逻辑全在 Python 里（`build_verdict` / `build_categories`）
- **自包含单文件**：CSS 内联，无任何外部字体 / 图片 / JS；原始 JSON 以 base64 data URI 内嵌（106 KB），断网也能打开、可直接转发
- **红黄绿判定**：≥80 可上线 / 70-79 有条件通过 / <80 不可上线，门槛是脚本常量，不散落在模板里
- **主因自动生成**：取分数最低的两个指标，映射成业务话术（例如 `answer_relevance` → 「答案与问题不相关（答非所问）」），并附证据句
- **行动项**复用 Day 13 的 analysis 建议，按优先级取前 3 条
- **badcase 展示前 20 条**（全量 55 条在原始数据里），回答超过 600 字截断，避免单条撑爆页面
