# Day 12：评测执行引擎

> 项目三第 2 周 · 让评测从「跑 10 条」到「跑 1000 条」：并发、重试、缓存、断点续跑。

## 一、为什么需要执行引擎

| 问题 | 不做引擎的后果 | 引擎的解法 |
|------|--------------|-----------|
| 串行执行太慢 | 100 条用例跑 40 分钟 | 并发 5-10 路 |
| API 偶发失败 | 整批评测中断，前功尽弃 | 指数退避重试 |
| 重复跑同样的题 | 每次都花钱花时间 | 内容 + 版本号缓存 |
| 跑到一半崩了 | 从头再来 | 断点续跑 |
| 结果散落各处 | 无法分析 | 统一存储 |

## 二、EvalRunner（`engine/runner.py`）

### 2.1 结构

| 能力 | 实现 | 关键点 |
|------|------|--------|
| 并发 | `asyncio.Semaphore` + `asyncio.to_thread` | 评测是 IO 密集型，线程池跑同步的问答函数，信号量控并发 |
| 重试 | `_run_with_retry` | 指数退避 `backoff_base * 2^attempt`，`backoff_base` 可配置（测试用 0.01s） |
| 缓存 | `_cache_key` = MD5(问题 + Prompt 版本) | 命中缓存不调用被测应用；版本变化自动失效 |
| 结果收集 | 预分配列表按下标写入 | 并发完成后结果顺序与输入一致，下游不用排序 |
| 失败隔离 | 单条三次失败只记 `TaskResult(success=False, error=...)` | 不抛异常、不中断整批 |

### 2.2 缓存与写入安全

缓存和 checkpoint 都采用**临时文件 + `os.replace` 原子写**，避免进程被杀时留下半截 JSON（读到坏文件时缓存视为未命中，checkpoint 视为空，都只降级不崩溃）。

### 2.3 断点续跑

`run(cases, qa_func, prompt_version, checkpoint=ckpt)`：

1. `checkpoint.is_done(case_id)` 为真 → 直接读缓存，标记 `skipped=True`
2. 否则查缓存 → 命中则记 `cached=True`
3. 都没有才真正调用，成功后先写缓存、再 `mark_done`（保证「已完成」一定有缓存可复用）

`Checkpoint`（`engine/checkpoint.py`）按 `run_id` 独立存文件，不同评测任务互不干扰。

## 三、结果存储 Schema（`sql/schema.sql`）

| 表 | 作用 | 关键字段 |
|----|------|---------|
| `eval_runs` | 一次评测一行 | prompt_version / dataset_name / model_name / total_score / status |
| `eval_results` | 一条用例一行 | question / answer / contexts / metrics(JSONB) / rule_details(JSONB) / passed / duration_ms |

指标用 `JSONB` 而不是宽表：本周指标还在快速迭代（Day 8-11 一直在加），加指标不该改表结构；同时保留 `passed` 独立列并建 `(run_id, passed)` 索引，失败用例查询不走 JSON 解析。

## 四、性能实测（20 条用例，本机 CPU）

| 场景 | 耗时 | 相对串行 |
|------|------|---------|
| 串行（并发 1） | 1.44s | 1.00x |
| 并发 5 路 | 0.93s | 1.55x |
| 缓存命中（同目录重跑） | 0.17s | 8.47x |
| 断点续跑（跳过 5 条） | 0.91s | — |
| 模拟 LLM 延迟 300ms/条 | 6.43s → 1.39s | **4.63x** |

**为什么本地真实场景只有 1.55x**：当前被测应用的生成是 mock（直接拼上下文），单条仅 0.072s，整批被 CPU 和 Python 解释器开销主导，并发收益有限。评测引擎的目标场景是**每次调用要等 200-800ms 的 LLM**，所以补了一组「模拟 300ms IO」实验：5 路并发拿到 4.63x，接近理论上限 5x。

**1000 条估算**：按每条 0.072s 算串行 1.2 分钟；接入真实 LLM（按 0.5s/条）后串行约 8.3 分钟，5 路并发约 1.7 分钟。

### 并发调参建议

- 从 5 路起步，观察 429 错误率，再逐步加到 10-20
- LLM API 有 QPS 限制，并发过高会大量触发限流，反而更慢
- 本地模型按 CPU/GPU 核数设置，别超过物理并行度
