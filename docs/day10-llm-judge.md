## 二、LLMJudge 设计

### 2.1 单维度打分

`score(question, answer, ground_truth)` 只评「正确性」一个维度，rubric 固定 6 档，禁止模型自由发挥：

| 分数 | 判定标准 |
|------|---------|
| 5 | 完全正确，事实准确，与标准答案一致 |
| 4 | 基本正确，仅措辞或细节微小差异 |
| 3 | 部分正确，有遗漏 |
| 2 | 勉强相关，含错误信息或严重遗漏 |
| 1 | 基本不相关，答非所问 |
| 0 | 完全错误或拒绝回答 |

返回值归一化到 0-1（`score`），同时保留 `raw_score` 便于和人工分对齐。

### 2.2 输出解析容错

实际模型经常输出 ```json 包裹或前后加解释文字，`_parse_json()` 先剥 code fence，再截取首个 `{` 到末个 `}`，避免「解析失败」被当成 0 分垃圾数据。

### 2.3 无 API Key 降级

`LLM_API_KEY` 缺失时自动走 `source=fallback`：用 Day 9 的语义相似度映射 0-5 分（≥0.93→5、≥0.87→4、≥0.80→3、≥0.70→2、否则 1）。降级结果**不能**当真实 Judge 结论使用 —— 下面的校验数据已经证明它拦不住否定句和数字陷阱。

## 三、忠实度 Judge

核心是**拆原子论断**：直接问「答案是否忠于上下文」，模型会给笼统好评；拆成论断后必须逐条核查，幻觉无处可藏，拆解结果本身也是 badcase 素材。

- 拆解规则：按 `。！？；\n` 切句 → 剥离「您好/感谢您的咨询/祝您」等客套前缀 → 丢弃 <6 字的碎片
- 计分：`score = 有支撑的论断数 / 论断总数`，并返回 `unsupported` 列表
- 降级核查：论断的**中文二元组**有多少比例出现在上下文里，≥40% 视为有支撑

实测示例：

```
答案：退款会在审核通过后3-5个工作日原路退回。全场包邮且支持货到付款。
上下文：退款将在审核通过后 3-5 个工作日内原路退回支付账户。
结果：score=0.5，unsupported=["全场包邮且支持货到付款"]
```

## 四、偏差控制（4 类）

| 偏差 | 表现 | 控制手段 | 代码落点 |
|------|------|---------|---------|
| 位置偏差 | 对比时总偏好第一个 | 双向调用（A/B 交换）取一致才判胜负，否则平局 | `compare_pair()` |
| 长度偏好 | 偏好更长的答案 | rubric 明写「答案长短、客套话多少不计入评分」 | `SCORE_RUBRIC` |
| 自我偏好 | 偏好同族模型输出 | `JUDGE_MODEL` 独立配置，Judge 与生成模型分离 | 构造函数 |
| 格式偏好 | 偏好 Markdown 排版 | rubric 声明「排版、分点还是成段不影响评分」 | `SCORE_RUBRIC` |

位置偏差的单测验证：让假模型永远返回 `winner=A`，`compare_pair` 交换顺序后结果映射为 B → 两次不一致 → 判平局，不会稳定偏向某一侧。

## 五、一致性校验结果（实测）

```
样本数: 20
一致率: 75.0%（允许 1 分误差）
平均绝对误差: 0.85 分
不一致: 5 条
```

| 样本 | 人工分 | Judge 分 | 原因 |
|------|-------|---------|------|
| jv_013 运费谁承担 | 3 | 5 | 答案只说了质量问题一侧，漏掉「非质量问题用户承担」 |
| jv_017 可以指定快递吗 | 0 | 2 | 结论相反（「可以指定顺丰」vs「暂不支持」） |
| jv_018 保修多久 | 1 | 5 | 数字互换（1 年/2 年），相似度 0.98 |
| jv_019 支持 5G 吗 | 0 | 2 | 否定句（「不支持」vs「支持」） |
| jv_020 能改地址吗 | 0 | 2 | 否定句（「已发货也可以改」vs「无法修改」） |

**结论：75%，未达 80% 门槛。** 5 条不一致全部是 Day 9 已确认的语义相似度固有短板（否定句、数字、结论相反），说明降级模式只能做粗筛。这组数据正是接入真实 LLM 后的回归基线 —— 要求 Judge 把这 5 条全部纠正，一致率应达到 ≥90%。
