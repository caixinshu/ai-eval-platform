五、本周最重要的三个决策

1. 长任务取消用「标记位 + 逐条检查」，而不是强杀线程

Python 线程无法被安全中断。改成前端置 cancel_requested，执行循环每处理一条读一次，命中则不再发起新请求。代价是并发窗口内最多多跑 3 条，收益是结果与进度自洽。再配两件兜底：整体 30 分钟超时置 failed；服务重启时把残留 running 统一置 failed，前端不会永远转圈。

2. 缺失数据不伪造，口径不可比就不比

雷达图缺忠实度就返回 null 留空档，而不是用 0 冒充「极差」；版本对比只画两次都存在的指标；趋势与分类统计限定在同一数据集内——黄金集和对抗集的分数直接比没有意义。图表的颜色也只表达结论：低于 70% 红、80 分及格线，不看刻度就能判断。

3. 部署细节本身就是功能

浏览器实测时页面一直「加载中」，排查发现 Windows 把 .js 映射成 text/plain，浏览器静默拒绝执行 ES module。修复只有两行 MIME 注册，但没有浏览器验收就永远发现不了。类似地，Nginx 默认 1m 上传限制会让 500 条用例直接 413、60 秒超时会让报告接口 504——这些都不是「部署杂事」，而是用户能不能用。

六、踩坑与修复

问题根因修复
页面停在「加载中」，无报错Windows 注册表把 .js 识别为 text/plain，ES module 被拒绝执行启动时强制注册 MIME，加测试断言 Content-Type
已有 SQLite 库启动报缺列create_all 不会给旧表加字段开发库轻量 ALTER 迁移，生产仍走 schema.sql
版本对比被旧回答污染引擎缓存 key 只有问题 + Prompt 版本评测服务关闭缓存，避免跨轮次复用
取消/超时难以测试TestClient 会等 BackgroundTasks 执行完测试直接 asyncio.run 调服务并预置状态
长任务写库偶发锁等待逐条 commit 放大 SQLite 写事务每 5 条提交一次，短事务 + 单会话
看板出现「假 0 分」缺失指标被默认成 0返回 null + missing 列表，图下注明暂无数据

七、遗留与风险

  • 待验证本机无 Docker，镜像与 Compose 未实机构建，仅完成 YAML 校验
  • 数据口径无真实 LLM Key，Judge / 生成仍走 mock 降级，质量分仅供参考
  • 功能缺口数据集缺删除/编辑接口；Prompt 仅发起页弹窗创建，无独立管理页
  • 安全无登录、权限与多租户，仅适合内网单人使用
  • 扩展性任务跑在本进程 BackgroundTasks，多副本部署需换 Celery / RQ
